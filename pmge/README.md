# PMGE — Procedural Mountain Generation Engine

Библиотека процедурной генерации гор по ТЗ `PMGE_Claude_Code_TZ_v2` (12.11.2026).
Версия 0.1.0 — **CPU-ядро и запросный API**. Это не весь объём ТЗ: что сделано и что нет —
в разделе «Статус» ниже и в `docs/STATUS.md`.

Принцип из ТЗ соблюдён: сначала структура (граф хребтов, вершины, перевалы, отроги,
долины), шум — только мелкая деталь. Высота — непрерывная функция `H(x, y)`, поэтому точка,
гекс, растр и соседние чанки берутся из одной поверхности и не имеют швов.

## Сборка

Нужны CMake 3.20+ и компилятор C++20 (GCC 11+, Clang 14+, MSVC 2022).
Внешних зависимостей нет.

### Windows (PowerShell, Visual Studio 2022)

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release
```

Библиотека: `build\Release\pmge.dll`.

### Linux / macOS

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
```

```bash
cmake --build build -j
```

```bash
ctest --test-dir build
```

Библиотека: `build/libpmge.so` (`libpmge.dylib` на macOS).

**Проверено только на Linux (GCC 13).** Сборка под MSVC и на macOS не запускалась; код
написан с учётом этих платформ (экспорт `__declspec`, `_putenv_s` в тестах, `/fp:strict`).

## Быстрый пример (C)

```c
#include "pmge/pmge.h"

pmge_request r;
pmge_request_init(&r);                 /* разумные значения по умолчанию */
r.seed = 482913;
r.center_x = 120000; r.center_y = 45000; r.radius_m = 6000;
r.base_m = 300; r.min_m = 300; r.max_m = 2800;
r.peak_count = 5;

pmge_plan* plan = pmge_plan_create(&r, NULL, 0);
double h = pmge_sample_height(plan, 120500, 45200);   /* без построения карты */
pmge_plan_destroy(plan);
```

Пять сценариев интеграции (точка, только гексы, локальный патч, хребет по линии,
продолжение через чанки) — `examples/scenarios.c`, собираются и запускаются в `ctest`.

Утилита: `build/pmge_cli --mode circle|box|line --size 512 --seed 7 --peaks 5
--types sharp=1,flat=0.5 --maturity 0.2 --erode thermal|fluvial|none --out out`
пишет `out.pgm` (16 бит) и `out.json` (план).

## Что умеет

| Возможность | API |
|---|---|
| План по области: круг, прямоугольник, полилиния | `pmge_plan_create` |
| План по чужой структуре (хребты и долины от геологической модели) | `pmge_plan_create_external` |
| Главный хребет, вершины, перевалы-седловины между соседними вершинами, отроги на обоих склонах, отроги второго порядка, долины между отрогами, предгорья | внутри плана |
| 8 типов вершин: острые, зубчатые, округлые, купол, столовые, игла, вулкан с кратером, усечённые | `peak_type_weights` |
| Одиночная гора: рог с гребнями-аретами либо одна постройка (вулкан, купол, стол) | `peak_count = 1` |
| Возраст гор: молодые — острые гребни, V-долины; старые — широкое тело, сглаженные гребни, U-долины | `maturity` |
| 4 профиля предгорий: плавные, холмистые, обрывистые, террасированные | `foothill_profile` |
| Высота в точке и пакетом, без карты | `pmge_sample_height`, `pmge_sample_batch` |
| Статистика по гексам: центр, среднее, min/max, дисперсия, уклоны, экспозиция, доля гор, расстояние до гребня, ближайший перевал, класс | `pmge_sample_hexes` |
| Heightmap любой области и шага | `pmge_generate_heightmap` |
| Локальный патч как дельта; вне области ровно 0; политики replace / add / max / masked / constrained_fit | `pmge_generate_patch` |
| Две модели эрозии на растре: термическая (сохраняет массу) и по стоку (stream power) | `pmge_erode_thermal`, `pmge_erode_fluvial` |
| План в JSON со стабильными ID вершин | `pmge_plan_json` |
| Проверка запроса с понятной причиной отказа | `pmge_validate`, `pmge_last_error` |

Единицы: метры и градусы. Жёсткие пределы `min_m` / `max_m` не нарушаются:
вершины упираются в мягкий «потолок» точечно, карта никогда не нормализуется целиком.

## Детерминизм и потоки

Одинаковые запрос, сид и версия библиотеки дают побитово одинаковый результат; случайность
только из хэша сида (splitmix64), без глобального состояния. Растры, пакеты точек и гексы
считаются параллельно (`PMGE_THREADS`, по умолчанию все ядра); каждое значение считается
независимо, поэтому число потоков на результат не влияет — это проверяется тестом.
Компиляция без fast-math (`-ffp-contract=off`, `/fp:strict`).

## Замеры

Intel Xeon 2,1 ГГц, 4 ядра, Linux, GCC 13, Release. Хребет 200 км по полилинии; время
включает построение плана и запись файла.

| Задача | Время | Цель ТЗ |
|---|---|---|
| Heightmap 512² | 0,22 с | до 0,5 с |
| Heightmap 2048² | 2,35 с | до 3 с |
| Heightmap 4096² | 8,3 с | до 10 с |
| Эрозия по стоку 2048², 12 итераций (вместе с картой) | 9,6 с (однопоточная эрозия) | замерять отдельно |
| 1 000 000 точек `sample_batch` | 1,7 с (до распараллеливания) | — |
| 100 000 гексов: центр / вершины / равномерно | 0,18 / 1,07 / 3,27 с (до распараллеливания) | — |

8192² и потоковые чанки не замерялись.

## Связь с HexWorld

HexWorld строит структурный план гор из своей геологической истории и передаёт его PMGE
через `pmge_plan_create_external` (ctypes, `src/hexworld/mountains/pmge_binding.py`).
PMGE возвращает рельеф гор как дельту; HexWorld применяет её только внутри горных систем.
Если библиотека не собрана, HexWorld использует свой встроенный модуль и пишет об этом
предупреждение. Подробно — `docs/integration.md`.
