## 3. Расхождения и как они решены

1. **Широта.** ТЗ 4.0 требует явной привязки к условным широтам. В v3 широт нет.
   Решение: параметр `climate.latitude_center_deg` (широта центра области симуляции) и
   `climate.km_per_degree` (0 — реальные 111,2 км/°). Если область при реальном масштабе
   прошла бы через полюс, шкала сжимается, и в предупреждениях пишется, во сколько раз.
   Север — вверх карты (−y).
2. **Слой `erosion_total_m`.** В v3 он уже есть и означает эрозию за историю. Чтобы не
   смешивать, v4 пишет свои поля как `v4_erosion_m`, `v4_deposition_m`, `erosion_rate_m_ma`,
   `v4_delta_elevation_m`; `pre_erosion_elevation_m` — это `elevation_m` v3 без изменений.
3. **Какой `elevation_m` главный.** После v4 итоговой поверхностью проекта становится
   высота после эрозии (`Project.layer("elevation_m")` возвращает её); слои v3 доступны
   через `Project.stage_layer("v3", ...)` и в инспекторе как `v3_*`. Суша и море v4
   считаются только из итоговой высоты.
4. **Глубина пересчёта.** До v4 функции `derive_landmasses`, `generate_v2`, `select_epoch`
   вызывали генерацию «до последней стадии по умолчанию», так что смена уровня моря у
   проекта v2 молча досчитывала геоисторию. Теперь проект сохраняет свою глубину
   (`api.stage_depth`): v2 остаётся v2, проект с v4 пересчитывает v4.
