## 2. Неприкосновенная основа из v1.0

- Ядро отделено от GUI; Python 3.12+, NumPy/SciPy, PySide6, pytest/ruff — без замены стека без причины.
- `flat-top` гексы, `odd-q` для массива, `axial/cube` для операций; карта — окно в **физические мировые координаты**, а не замкнутая фигурка на экране.
- Размеры 100×100 и больше, пресеты 500×300 и 1000×800. Качество и детерминизм важнее скорости.
- Сид из `0-9A-Za-z`, регистр значим; отдельный RNG namespace `continents/v2`, `macro_relief/v2`, `sea_level/v2`. Результат не зависит от порядка перерисовки вкладок.
- **Plate ID, геометрия плит и тектонические поля v1.0 остаются теми же**, если изменены только параметры v2.0.
- Не допускать принудительного океана или замыкания континентов на границах `viewport`. Региональные карты могут показывать *фрагмент* большого материка.
- У v1.0 уже было грубое поле `crust_type`. Использовать его как входной **геологический prior**, а не объявлять автоматически точной границей будущей суши. При уточнении хранить результат v2 отдельно; не перезаписывать оригинальное поле.

## 3. Что представляют новые географические объекты

Разделить понятия и соответствующие данные:

| Объект | Смысл | Может пересекать плиты? |
|---|---|---|
| **Континентальный блок** | Связный массив континентальной коры, включая подводную часть | Да |
| **Материк / надводная суша** | Связный массив ячеек с высотой **выше уровня моря** | Да |
| **Континентальный шельф** | Затопленная часть континентальной окраины; на v2 грубая оценка | Да |
| **Океанический бассейн** | Преимущественно океаническая кора с отрицательной высотой относительно моря | Да |

**Принципиально:** граница континентальной коры ≠ береговая линия ≠ граница литосферной плиты. Один континентальный блок может включать несколько плит; одна плита может нести несколько континентальных фрагментов и океаническую кору. Некоторые участки континентальной коры находятся под водой.

### Минимальные выходные поля

Хранить в физической географической модели, а на гексы передавать через существующий сэмплер:

```text
continental_fraction       float32 [0..1] (непрерывная доля/признак континентальной коры)
continental_block_id       int32 (-1 = нет блока)
macro_elevation_m          float32 (метры, в единой вертикальной системе отсчёта)
sea_level_m                float, параметр текущего сценария
land_mask                  bool (macro_elevation_m > sea_level_m)
landmass_id                int32 (-1 = под водой; связная надводная суша)
shelf_mask                 bool (грубый подводный континентальный шельф)
```

Также сохранять метаданные блоков/материков: `id`, площадь (км²), центр и границы в мировых координатах, степень связи с плитами, площадь суши/подводной части, соседство. `landmass_id` **не обязан** совпадать с `continental_block_id`. Названия можно генерировать детерминированно, но название не должно определять геометрию.

Морские глубины вычислять относительно уровня моря: `depth_m = max(0, sea_level_m − macro_elevation_m)`; наземные высоты аналогично `max(0, macro_elevation_m − sea_level_m)`. Не создавать противоречивых независимо генерируемых карт «высот» и «океана».

## 4. Генерация континентов: необходимые свойства

**Приоритет — правдоподобная геологическая структура, а не шумовая маска.** Конкретный алгоритм выбирает Claude Code после короткого исследования существующих решений; комбинация структурных регионов/графов и многомасштабной коррекции разрешена.

Требования:

1. **Крупный масштаб сначала.** Располагать несколько разных по площади континентальных ядер/блоков, создавать их соединения, выступы и разрывы. Не выводить целые материки из числа плит или единственной диаграммы Вороного.
2. **Тектоническая привязка.** В зонах континентальной коллизии возможны соединение массивов и области поднятия; в рифтах — вытянутое ослабление, разделение или узкие морские бассейны; при субдукции — ориентированная по границе крупная орография и впадины; пассивные окраины — более плавные переходы и шельфы. Не применять каждый эффект ко всем границам без учёта типа коры.
3. **Нерегулярная геометрия.** Допускать длинные полуострова, заливы, перемычки, проливы, разные степени изрезанности. Контур должен быть сложным на разных масштабах, но без бахромы из случайных одиночных клеток и без одинаково округлых «клякс».
4. **Разные конфигурации.** Нормальны несколько разделённых материков, один большой с меньшими спутниками, суперконтинент, фрагментированный мир. Размеры не обязаны быть одинаковыми.
5. **Разрешение не определяет геологию.** Строить структуру в мировых координатах или на фиксированной опорной сетке; гексы и визуальные пиксели только сэмплируют её. При смене 500×300 ↔ 1000×800 тот же физический мир должен сохранять узнаваемые материки (погрешность ограничена дискретизацией).
6. **Границы viewport не географические границы.** Континенты могут входить и выходить из видимой области; не добавлять автоматически океан по периметру и не стремиться уместить каждый материк целиком.

Искусственный шум допустим для умеренной детализации, но не может быть единственной причиной положения суши. Для первой версии допустим **приближённый снимок** влияния тектоники без временного движения плит; предусмотреть последующую замену на полноценную историю.

## 5. Первичная карта высот и уровень моря

Сформировать **одно** скалярное поле абсолютной макровысоты, из которого выводятся суша и море. Использовать строение коры и приближённые тектонические воздействия: океаническое дно преимущественно ниже, континентальные плато/равнины — выше, коллизионные области подняты, рифтовые зоны понижены, океанические желоба и шельфы имеют соответствующие крупные формы. Переходы непрерывны и не совпадают механически со всеми границами плит.

Это **макрорельеф**, не завершённая heightmap. Детальные пики/хребты, фьорды, русла, ледниковые формы, локальные вулканы, эрозионные долины позже добавятся **поверх и с учётом** этой основы, а не путём её полной замены.

Управление морем — два взаимоисключающих режима:
- `target_land_fraction`: генератор подбирает `sea_level_m` к желаемой доле суши **в выбранной физической области**, учитывая, что региональное окно может иметь другую долю;
- `fixed_sea_level_m`: пользователь задаёт уровень напрямую, фактическая доля суши вычисляется и показывается. Не пытаться одновременно принудительно выдержать оба значения.

При изменении только уровня моря перерассчитать `land_mask`, `landmass_id`, береговую маску/шельф и отображение — **без пересоздания плит, континентальной коры и макровысот**. Колебания моря должны приводить к закономерному затоплению низин, появлению островов, проливов и шельфов.

На v2.0 разрешены отдельные небольшие острова, **возникшие из рельефа и уровня моря**, включая континентальные фрагменты. **Не** делать пока отдельную генерацию вулканических цепочек, атоллов, барьерных островов и точных береговых типов — это следующие версии.

## 6. Настройки v2.0

В GUI и конфигурации добавить:

| Параметр | Поведение |
|---|---|
| `continent_profile` | `balanced` / `supercontinent` / `fragmented` |
| `major_landmass_count` | `auto` или желаемое количество **крупных** надводных массивов в *simulation_bounds*; это цель, а не гарантия для обрезанного viewport |

Начальные значения выбирает Claude Code и документирует в пресетах, без жёсткой подгонки под одну-единственную картинку. Если параметр недостижим или противоречив, показывать предупреждение и фактический результат. Не вынуждать алгоритм ломать тектоническую структуру ради точного числа материков.

## 7. GUI: постоянные вкладки географических слоёв

**Это требование относится ко всему HexWorld, не только ко второй версии.** После реализации новые генерационные ступени добавляют свои вкладки/слои через единый интерфейс, сохраняя уже существующие.

Единое окно приложения: общий viewport, zoom/pan, выбор гекса/области, панель свойств, сид, настройки, генерация, открытие/сохранение. В верхней части карты **вкладки**:

| Вкладка | Реально показывает в v2.0 |
|---|---|
| **Плиты** | v1.0: цвета и ID плит, границы, стрелки движения, классы границ; переключаемые прежние диагностические поля |
| **Материки** | отдельные цвета континентальных блоков **или** надводных материков (подрежимы), граница суши, затопленные континентальные окраины/шельфы |
| **Высоты** | `macro_elevation_m` цветовой/серой шкалой, высота и глубина в метрах, положение уровня моря; опционально изолинии |

- Переключение вкладки меняет **только представление**, не запускает генератор и не меняет seed/высоты/плиты. Zoom/pan и выбранная точка остаются общими.
- У каждой вкладки своя легенда, доступные переключатели наложений и понятная подпись **«Макрорельеф v2.0 (без детализации и эрозии)»** на вкладке высот.
- Клик на объект отображает данные: `plate_id`, `continental_block_id`, `landmass_id`, тип/доля коры, высота, глубина, уровень моря, по возможности диагностические значения.
- Пользователь должен уметь видеть различие **геологических континентальных блоков** и **надводной суши**, а не получать одну общую картинку «континентов».
- Сделать простой реестр доступных вкладок/слоёв (`id`, имя, источник поля/рендерер, легенда, оверлеи, статус готовности). В будущем можно добавить «Реки», «Климат», «Биомы», «Геосимволы» без переписывания карты.
- Пока несуществующие слои не изображать готовыми: скрыть либо показывать как **отключённые** с подписью «Запланировано».
- Производительность: отрисовка партиями/тайлами, не один PySide-виджет на гекс; генерация в фоне от GUI-потока, без потери старых данных при отмене.

## 8. Конвейер, сохранение и обратная совместимость

Новые стадии **после выходов v1.0**:

```text
v1: world → plates → prior_crust → motion → boundary_edges → tectonic_fields
                                                         ↓
v2:                           continental_blocks → macro_elevation → sea_level_landmasses
                                                         ↓
                          save/export → hex_samples → Plates / Continents / Heights tabs
```

- Выходы v1.0 неизменны; v2.0 имеет собственные RNG namespace, параметры, версии алгоритмов и пересчёт зависимых стадий. Изменение формы материков не двигает плиты; изменение уровня моря не переписывает кору.
- Продлить `config.json` настройками `continents` и `sea`; хранить `continental_blocks`/`landmasses` метаданные и новые типизированные поля в отдельном файле (`continental_fields.npz` или версионированный аналог); обновить `manifest.json` с размерами, единицами, хэшами, `schema_version`.
- Проекты v1.0 **должны открываться**: до запуска новой стадии показывать существующие слои плит и пометку «Материки/Высоты ещё не сгенерированы»; предложить запуск v2. Не подменять отсутствие данных нулями или нарисованной заглушкой.
- Загрузка/сохранение v2.0 восстанавливает вкладки, численные поля, параметры и режим моря. Не перезаписывать без спроса оригинальные v1.0 данные; если требуется миграция — копия и документированное преобразование.
- Экспортировать численные карты и таблицы, а также PNG каждой вкладки **по отдельности**. PNG не считать источником географических данных. Короткий Python API: `generate_continents(v1_world, config)`, `generate_macro_relief(v1_world, continents, config)`, `derive_landmasses(relief, sea_level)`, `get_layer(id, bounds, resolution)`; конкретные имена могут быть уточнены без нарушения смыслового контракта.
- Для будущего PMGE предусмотреть передачу **макрорельефа + областей геологического поднятия/масок континентов + мировой системы координат** независимому генератору гор. Не включать C++ PMGE в обязательные зависимости v2.

## 9. Приёмка и проверки

1. **Совместимость:** открыть v1-проект, не изменяя его карты плит/seed; сгенерировать v2; сохранить и открыть снова. Хэши прежних полей v1 совпадают.
2. **Три вкладки:** переключаются мгновенно без генерации, одинаковые координаты/выделение, корректные легенды, экспорт каждой в PNG. «Материки» умеет переключаться между блоками коры и фактической сушей.
3. **Повторяемость:** один seed, физическая область, конфигурация и версия → идентичные v2-массивы и хэши в закреплённой среде; разные рендер-настройки не меняют данные.
4. **Физическая связность:** `land_mask` выводится только из высоты и уровня моря; каждый надводный гекс принадлежит ровно одному `landmass_id`, морской — ни одному; блоки/массивы проверены на связность по общей стороне гексов.
5. **Изменение моря:** подъем уровня не увеличивает суммарную площадь суши; не изменяет высоты/плиты/континентальную кору; закономерно образует/затапливает острова и проливы.
6. **Качество форм:** протестировать не менее 10 разных seed и три профиля. Визуально нет стандартных круглых пятен, регулярной мозаики, необъяснимой «бахромы», насильственного океана по краю; континенты и впадины достаточно различаются по размерам и конфигурациям. Сохранить диагностические изображения.
7. **Реальная масштабируемость:** запуск 100×100, 500×300, 1000×800 (Windows-путь в README), записать фактическое время/память. На крупной карте интерфейс остаётся отзывчивым.
8. **Проверка границ окон:** совпадающая физическая область в двух viewport/resolution сохраняет крупные формы материков, профили высот и положение геологических блоков в пределах ожидаемой ошибки дискретизации.

1. Проверить состояние существующего репозитория HexWorld и фактическую реализацию v1.0. Если какой-то обязательный контракт v1 отсутствует, **указать блокер** и исправить минимально необходимое, а не имитировать данные.
2. Кратко посмотреть примеры (их код/лицензии перепроверить перед использованием):
   - https://github.com/Mindwerks/worldengine
   - https://github.com/Guy-Shalev/terrain-generator
   - https://github.com/raguilar011095/planet_heightmap_generation
   - https://github.com/vnovak404/worldgen (пример интерфейса отдельных слоёв)
   - https://www.redblobgames.com/grids/hexagons/ (геометрия и связность гексов).
