# HexWorld

Процедурный генератор гексагональной географической карты.

- **v1.0 — тектоническая основа:** литосферные плиты, исходное поле коры, движение плит,
  граф границ, диагностические поля.
- **v2.0 — материки и макрорельеф:** континентальные блоки, единое поле макровысот,
  уровень моря, надводные массивы, шельф.
- **v3.0 — геологическая история:** прямая симуляция движения плит во времени, коллизии,
  субдукция, рифты и новая кора, журнал событий и снимки; горные системы со структурой
  хребтов, вулканические дуги и цепочки горячих точек, породы, ограниченная эрозия,
  итоговая высота.
- **v4.0 — климат, реки, эрозия:** температура, ветер, перенос влаги и дождевые тени,
  осадки, испарение, снег; сток по шести соседям гекса, озёра по водному балансу,
  бессточные бассейны, граф рек с порядком Стралера; речная и склоновая эрозия с балансом
  наносов в связке с климатом. Итоговые высоты, суша и море — после эрозии.

- **4.1 — горы и берега:** пояса делятся на системы разной архитектуры (альпийская,
  гималайская с плато, андская, складчатая, древний массив, нагорье, смешанная, глыбовая,
  вулканическая дуга) с параллельными хребтами, котловинами и нерегулярным ветвлением;
  17 типов берегов из причин (фьорды, шхеры, риасы, далматинские, клифы, дельты, эстуарии,
  лиманы, мангры, рифы, себхи, ватты, барьеры, пляжи...). Отчёт — `docs/REPORT_4.1.md`.

- **4.2 — сверка с инженерным мануалом:** четыре сезона (зима и лето противоположны в
  полушариях, пояса дождей и муссоны следуют за солнцем), массо-сохраняющий перенос влаги
  с замкнутым бюджетом, сезонный водный баланс гекса (снег, таяние по градусо-дням, почва,
  грунтовые воды, базовый сток), выходы воды из окна только там, где их даёт сток мира,
  маршруты стока не зависят от положения окна, порог речного размыва, ширина и глубина
  русел; приёмка по пунктам мануала (`tests/test_manual.py`). Отчёт — `docs/REPORT_4.2.md`,
  матрица соответствия — `docs/manual_compliance.md`.

- **PMGE** — отдельная библиотека гор на C++20 (`pmge/`), HexWorld вызывает её через C ABI;
  своя документация — `pmge/README.md`.

Ледников (кроме климатического потенциала), биомов и игровых
значков **ещё нет** — см. `docs/STATUS.md`. Отчёт по v4 — `docs/v4_implementation_report.md`;
сравнение с Землёй — `docs/realism_v4.md`. Разбор слабых мест модели и путей к большему реализму —
`docs/REALISM_ANALYSIS.md`.

Задания: `docs/HEXWORLD_TZ_1.0_Claude_Code.md`, `docs/HEXWORLD_TZ_2.0_CONTINENTS.md`,
`docs/HEXWORLD_TZ_3.0_GEOHISTORY_MOUNTAINS.md`, `docs/HexWorld_TZ_4.0_CLIMATE_HYDROLOGY_EROSION.md`.

## Установка

Нужен Python 3.12 или новее.

### Windows (PowerShell) — основная платформа

Всё сразу (окружение, HexWorld с просмотрщиком, PMGE, если есть CMake и Visual Studio
Build Tools):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\install.ps1
```

Запуск просмотрщика: `scripts\windows\hexworld_gui.bat`. Вручную:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[gui,dev]"
cmake -S pmge -B pmge\build
cmake --build pmge\build --config Release
```

Каждый коммит проверяется на Windows (Python 3.12 и 3.13) и Linux в GitHub Actions
(`.github/workflows/ci.yml`).

### Linux / macOS

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e ".[gui,dev]"
```

Ядро и CLI требуют только NumPy и SciPy. `gui` добавляет PySide6, `dev` — pytest и ruff.

## Запуск

Просмотрщик:

```bash
hexworld gui
```

Новый проект со всеми стадиями и PNG каждой вкладки:

```bash
hexworld generate --seed Ab12 --preset medium -o out/medium --png-views
```

Добавить геологическую историю к сохранённому проекту v2.0 (исходная эпоха не меняется):

```bash
hexworld history out/old_v2_project --duration-ma 40 --history-intensity earthlike
```

Добавить или пересчитать климат, реки и эрозию (v1–v3 не пересчитываются):

```bash
hexworld climate out/medium --climate-profile dry --latitude 20 --erosion-ma 3
```

Сравнить сгенерированный мир с Землёй (гипсометрия, климат, реки, размыв):

```bash
python tools/realism_report.py out/medium
```

Показать другой сохранённый снимок истории — без повторной симуляции:

```bash
hexworld epoch out/medium initial
```

```bash
hexworld epoch out/medium 15
```

Хронология событий:

```bash
hexworld events out/medium --until 10
```

Добавить материки и высоты к уже сохранённому проекту v1.0 (его данные плит не переписываются):

```bash
hexworld continents out/old_v1_project --continent-profile balanced
```

Изменить только уровень моря:

```bash
hexworld sea out/medium --level 120
```

```bash
hexworld sea out/medium --land-fraction 0.35
```

PNG всех вкладок и режимов, по одному файлу на каждый:

```bash
hexworld render out/medium --view all
```

Одна вкладка в нужном режиме:

```bash
hexworld render out/medium --view continents --mode blocks --overlays coast shelf
```

Таблицы CSV, реки в GeoJSON и числовые слои `.npy`:

```bash
hexworld export out/medium -o out/medium_export
```

Сведения, проверка, значения одного гекса, список вкладок:

```bash
hexworld info out/medium --plates
```

```bash
hexworld validate out/medium
```

```bash
hexworld hex out/medium 120 80
```

```bash
hexworld views
```

Если команда `hexworld` не найдена, то же делает `python -m hexworld ...`.
На Windows пути пишутся так же: `hexworld generate --preset large -o out\large`.

Тесты — одной командой:

```bash
python -m pytest
```

Нагрузочные тесты на 500×300 и 1000×800:

```bash
python -m pytest -m slow
```

### Параметры `generate`

| Параметр | Значение |
|---|---|
| `--seed` | строка из `0-9A-Za-z`, регистр значим: `Ab12` и `ab12` — разные миры |
| `--preset` | `small` 100×100, `medium` 500×300, `large` 1000×800 (все `regional`), `world` 1000×800 |
| `--width`, `--height`, `--hex-km` | сетка в гексах и расстояние между центрами соседних гексов, км |
| `--mode` | `regional` — окно в более обширный мир; `world` — окно показывает всю область симуляции |
| `--plates`, `--profile` | число плит (`auto` или целое) и профиль `few` / `earthlike` / `fragmented` |
| `--origin X Y`, `--sim-bounds` | положение окна и явная область симуляции (закрепляет мир) |
| `--continent-profile` | `balanced` / `supercontinent` / `fragmented` |
| `--major-landmasses` | `auto` или желаемое число крупных массивов в области симуляции — цель, не гарантия |
| `--size-variety` | 0…1: разброс размеров блоков и доля второстепенных фрагментов |
| `--coast-irregularity` | 0…1,5: крупно- и среднемасштабная неровность берегов |
| `--relief-strength` | 0…3: сила макротектонического поднятия и впадин |
| `--land-fraction` **или** `--sea-level` | режим моря: доля суши в области симуляции либо уровень в метрах |
| `--duration-ma`, `--time-step-ma` | длительность истории и шаг, млн лет (по умолчанию 30 и 1) |
| `--checkpoint-stride` | сохранять снимок каждые N шагов (по умолчанию 5) |
| `--history-intensity` | `calm` / `earthlike` / `active` |
| `--uplift-scale`, `--erosion`, `--hotspots` | множители поднятия, эрозии и числа горячих точек; 0 выключает |
| `--mountain-detail` | контраст структурного рельефа гор, 0…2 |
| `--mountain-style` | `auto` (по тектонике, ширине, возрасту и сиду) или одна архитектура для всех систем: `alpine`, `himalayan`, `andean`, `fold_belt`, `old_massif`, `broad_upland`, `mixed`, `block`, `volcanic_arc` |
| `--mountain-complexity` | 0 — один гребень на систему (как в 3.x), 1 — параллельные хребты, котловины, нерегулярные отроги, до 2 — больше |
| `--mountain-backend` | `auto` (по умолчанию: PMGE, если собран), `reference` или `pmge` |
| `--epoch` | какой снимок показать: `final`, `initial` или время в млн лет |
| `--climate-profile` | `earthlike` / `dry` / `wet` |
| `--latitude`, `--km-per-degree` | условная широта центра области (север — вверх карты) и масштаб широты; 0 — реальные 111,2 км/° (сжимается, если область перешла бы через полюс) |
| `--temperature-offset`, `--lapse-rate` | сдвиг всех температур, °C; вертикальный градиент, °C/км (6,5) |
| `--wind-strength`, `--precipitation-scale` | множители поясов ветров и общего количества осадков |
| `--river-threshold`, `--river-min-hexes`, `--river-system-hexes` | река: от расхода (25 м³/с) и водосбора (4 гекса); показывать системы с водосбором в устье от 8 гексов |
| `--routing` | `stochastic` (по умолчанию, сходящаяся сеть) или `steepest` (классический D6) |
| `--edge-outlets` | `world` (по умолчанию: вода уходит из окна там, где её уносит сток мира) или `all` (через любой краевой гекс, как в 4.0) |
| `--incision-threshold` | порог речного размыва E_c, м/млн лет (0 по умолчанию) |
| `--erosion-ma`, `--erosion-steps`, `--no-erosion` | длительность климатической эрозии v4 (2 млн лет) и число шагов связки (8) |
| `--no-v4` | остановиться после v3.0 |
| `--no-history` | остановиться после v2.0 |
| `--v1-only` | остановиться после тектонической стадии |
| `--config` | JSON со всеми параметрами, примеры в `examples/` |

Значения по умолчанию: профиль `balanced`, число массивов `auto`, разброс 0,5,
изрезанность 0,7, сила рельефа 1,0, доля суши 0,29.

## Что такое что

| Объект | Слой | Смысл |
|---|---|---|
| Плита | `plate_id` | литосферная плита; движется как целое |
| Континентальный блок | `continental_block_id` | связный массив континентальной коры, включая подводную часть |
| Материк, суша | `landmass_id`, `land_mask` | связный массив гексов выше уровня моря |
| Шельф | `shelf_mask` | затопленная континентальная кора не глубже 500 м |

Граница коры, береговая линия и граница плиты — три разные линии. Блок может лежать на
нескольких плитах, плита может нести несколько блоков и океаническую кору, часть
континентальной коры находится под водой. Суша определяется **только** как
`macro_elevation_m > sea_level_m`; глубина — `max(0, sea_level_m − macro_elevation_m)`.

Исходное поле коры v1.0 (`crust_type`) используется как геологический prior и не
перезаписывается: уточнённый результат v2 хранится отдельно в `continental_fraction`.

## Как устроена v2.0

Стадии идут строго после выходов v1.0 и только читают их:

```text
v1: world → plates → prior_crust → motion → boundary_edges → tectonic_fields
v2:   world_tectonics → continental_blocks → macro_elevation → sea_level_landmasses
```

1. **`world_tectonics`.** Границы плит прослеживаются в мировых координатах на фиксированном
   растре и привязываются к непрерывной границе модели плит. Граф границ v1.0 живёт на гексах
   одного окна, а материки не должны зависеть от окна — поэтому нужен этот каркас.
2. **`continental_blocks`.** Знаковое поле «расстояние до края коры» собирается из четырёх
   частей, от крупного к мелкому:
   - массивы prior-коры, с индивидуальным ростом или сжатием блоков;
   - структура: широкие зоны спайки соседних блоков и рифты. Рифт идёт по границе плит,
     пересекающей блок, если такая есть;
   - тектоника: сближение двух континентальных окраин закрывает промежуток, расхождение
     утоняет кору вдоль границы;
   - многомасштабная неровность берегов с амплитудой, пропорциональной длине волны.
   Профиль `supercontinent` стягивает узор коры к центру, `fragmented` уменьшает его масштаб;
   общая доля континентальной коры в мире при этом сохраняется.
3. **`macro_elevation`.** Одно поле высот в метрах: гипсометрия коры (абиссаль → склон →
   шельф → низменность → внутренние области), широкие поднятия и впадины, тектонические
   формы — коллизионные поднятия, поднятие над зоной субдукции с жёлобом и тыловой впадиной,
   срединно-океанические хребты, рифтовые впадины с плечами.
4. **`sea_level_landmasses`.** Уровень моря, маска суши, материки, шельф. Смена уровня моря
   пересчитывает только эту стадию.

Всё это — функции мировых координат, поэтому гексы любого окна и разрешения семплируют один и
тот же мир. Влияние тектоники — приближённый снимок по текущей кинематике, **не симуляция
геологической истории**.

## Как устроена v3.0

Исходная эпоха `t = 0` — мир v1/v2. Он только читается. История идёт вперёд до
`t = duration_ma` и создаёт новые снимки.

```text
v1 плиты / кора / кинематика  +  v2 материки / макровысота
  → geo_history    шаги времени, снимки, события, вулканы, эрозия
  → mountain_plan  структура гор выбранной эпохи
  → v3_raster      итоговая высота и все слои v3 на гексах
  → суша и море    одна поверхность, один уровень моря
```

1. **Движение.** Плиты жёсткие. Контур плиты в момент `t` — её исходный контур, сдвинутый
   точным жёстким преобразованием. Поэтому геометрия не размывается, а столкновение
   нельзя «перепрыгнуть» большим шагом.
2. **Взаимодействия из геометрии.** Где контуры перекрылись — плиты сближаются:
   континент на континент — коллизия, что угодно на океаническую кору — субдукция
   (всплывает более лёгкая порода; из двух океанических плит тонет более старая).
   Где между контурами разрыв — расхождение: рождается новая кора. Узкий разрыв между
   континентальными окраинами — рифт, ещё не океан.
3. **Память породы.** Поднятие, эрозия, осадки и возраст горообразования копятся в
   материальной системе плиты, поэтому пояс едет вместе с плитой.
4. **Рельеф взаимодействий.** Коллизия поднимает обе стороны; над зоной субдукции растёт
   дуга со стороны верхней плиты, у края нижней — жёлоб, в тылу — впадина; у рифта — впадина
   с плечами; новое дно углубляется с возрастом как `2600 + 350·√возраст` м.
5. **Вулканизм.** Горячая точка неподвижна в мантии; плита над ней движется, и постройки
   выстраиваются в цепочку с нарастающим возрастом. Дуговые центры появляются на верхней
   плите на расстоянии дуги от действующего жёлоба. Сдвиг и коллизия вулканов не дают.
6. **Эрозия.** Склоновая диффузия и размыв стоком с учётом сопротивления породы; снятый
   материал откладывается на пологих участках и у берега. Баланс сохраняется в журнале.
7. **Горы.** Сначала структура: системы → главный хребет по гребню пояса → ветви и
   отроги → вершины и перевалы-седловины между ними → долины между отрогами. Затем высоты.
   Острота и контраст зависят от возраста системы и доли снятого эрозией.
8. **Итог.** `elevation_m` выбранной эпохи; суша и море считаются из неё и из того же
   уровня моря, что в v2. Исходная макровысота доступна как `base_macro_elevation_m`.

Шаг времени делится на подшаги так, чтобы ни одна плита не проходила больше одной ячейки
растра истории за подшаг. 1 мм/год = 1 км/млн лет.

**Горный модуль.** HexWorld строит структурный план гор сам, а высоты гор считает PMGE
(`pmge/`) через C ABI. Собрать библиотеку:

```bash
cmake -S pmge -B pmge/build -DCMAKE_BUILD_TYPE=Release
```

```bash
cmake --build pmge/build -j
```

На Windows: `cmake -S pmge -B pmge\build` и `cmake --build pmge\build --config Release`.
HexWorld находит библиотеку в `pmge/build` или по переменной `HEXWORLD_PMGE_LIBRARY`.
Если библиотеки нет, работает встроенный модуль, и об этом пишется предупреждение
(`--mountain-backend auto | reference | pmge`).

## Как устроена v4.0

```text
v3: снимок эпохи (elevation_m, породы, поднятие, уровень моря, мировой растр)
  -> A. климат мира на растре ~60-90 км, 4 сезона: температура, ветер и муссоны,
        консервативный перенос влаги (бюджет E - P +- граница = dM), осадки
  -> приток воды из-за края окна и выходы из окна (грубая мировая сеть стока)
  -> B-E. связка, N шагов: климат гексов по сезонам -> снег, почва, грунтовые воды
          -> сток, озёра, расход
          -> поднятие -> stream power (неявно) -> склоновая диффузия -> наносы
  -> F. итоговый климат, гидрология и реки на итоговой поверхности; суша, материки, шельф
```

- **Широты.** Плоская карта привязана к условным широтам параметром широты центра;
  экватор и полюса могут лежать вне карты.
- **Климат** — параметризация, а не модель общей циркуляции: пояса ветров, перенос влаги
  с ветром, конденсация при подъёме на наветренных склонах и дождевая тень за ними,
  ВЗК и субтропические пустыни. С 4.2 — четыре сезона (DJF, MAM, JJA, SON): пояса
  смещаются к летнему полушарию, над материками сильнее; муссонный ветер дует к тёплой
  суше летом и от неё зимой. Перенос влаги — конечные объёмы против потока, вода не
  теряется и не берётся ниоткуда. Откалибровано по средним Земли (`docs/research_v4.md`).
- **Водный баланс гекса** по сезонам: доля снега, таяние по градусо-дням, почвенное
  «ведро» 150 мм, испарение по кривой Фу, быстрый сток, подпитка и разгрузка грунтовых
  вод; ледник отдаёт годовой прирост снега. P = ET + сток + потери + изменение запасов
  сходится в каждом гексе.
- **Край окна.** Вода уходит за край окна только там, где её уносит сток всего мира;
  остальные краевые гексы текут внутрь (`--edge-outlets world|all`). Случайный выбор
  нижнего соседа привязан к мировому положению гекса: два окна одного мира проводят сток
  одинаково.
- **Сток** идёт по шести соседям гекса. Впадины обрабатываются priority-flood на
  отдельной «маршрутной» поверхности, физическая высота не поднимается. Озеро
  переливается, если приток больше испарения, иначе сжимается до баланса или пересыхает.
- **Реки** — граф сегментов-полилиний в мировых км с порядком Стралера, расходом,
  шириной, глубиной и скоростью (W = 5 Q^0,5, D = 0,3 Q^0,4), водосбором и устьем (`sea`, `lake`, `endorheic`, `window_edge`).
- **Эрозия** — stream power по расходу (влажные бассейны режут сильнее; порог
  `--incision-threshold`, м/млн лет), склоновая
  диффузия, перенос и отложение наносов; каждый кубометр учтён в балансе.
- **Что пересчитывается.** Порог показа рек — только сеть рек; климат и эрозия — v4
  целиком; уровень моря или снимок эпохи — v4 для нового берега. Плиты и история — никогда.

  и эрозии)».

  высоту, глубину, уровень моря, тектонический вклад и диагностические значения.

- Генерация идёт в фоновом потоке; «Отмена» прерывает её после текущей стадии, прежние данные
  остаются.
- Источник высоты всегда подписан в легенде: итог v3 с временем снимка либо исходная
  макровысота v2.
- Список «Снимок» выбирает сохранённую эпоху; история при этом не пересчитывается.

  материк, порода, горная система и её возраст; где данных нет, так и написано.
- «Масштаб интерфейса» меняет размер шрифта и элементов.
- Вкладки «Биомы», «Геосимволы», «Сейсмичность» показаны отключёнными с пометкой

- Блок «Климат, реки, эрозия (v4.0)» на боковой панели: профиль климата, широта, масштаб
  широты, сдвиг температуры, множители осадков и ветра, длительность эрозии, порог реки,
  способ выбора направления стока; кнопка «Пересчитать только v4».
- В инспекторе выбранного гекса — отдельный раздел v4: высота до и после эрозии, широта,

Вкладки берутся из реестра `hexworld/views.py`. Новая стадия генерации добавляет свою вкладку
вызовом `register_view(...)`; виджет карты при этом не меняется.

## Совместимость с v1.0, v2.0 и v3.0

- Проекты `hexworld-project-3` открываются как есть; вкладки v4 пишут «не рассчитано».
  `hexworld climate` или кнопка «Пересчитать только v4» добавляют v4; файлы v1–v3 не
  переписываются, исходные `config.json`/`manifest.json` сохраняются как `*.v3.json`.
- Данные v4 другой версии алгоритма или от другой эпохи/конфигурации не загружаются,
  причина пишется в предупреждениях.
- Добавление v2 к проекту v1 или геоистории к проекту v2 больше **не** досчитывает
  последующие стадии молча: проект остаётся той глубины, которую просили.

- Проекты `hexworld-project-1` открываются как есть. Вкладка «Плиты» работает, на вкладках
  «Материки» и «Высоты» написано, что они ещё не сгенерированы, и есть кнопка запуска v2.
  Нулей или нарисованной заглушки вместо отсутствующих данных нет.
- При добавлении v2 файлы `plates.json`, `fields.npz`, `boundaries.npz`, `boundaries.json`
  не переписываются. Новые данные ложатся в `continental_fields.npz` и `continents.json`.
- `config.json` и `manifest.json` обновляются; исходные сохраняются рядом как
  `config.v1.json` и `manifest.v1.json`.
- Параметры v2 не входят в ключи стадий v1: `plate_id`, геометрия плит и тектонические поля
  остаются теми же.
- Проекты `hexworld-project-2` открываются как есть; вкладки v3 сообщают, что геоистория
  ещё не сгенерирована. При добавлении v3 файлы v1 и v2 не переписываются, новые данные —
  в `history_fields.npz`, `history.json`, `events.json`, `checkpoints.npz`,
  `mountain_plan.json`; исходные `config.json` и `manifest.json` сохраняются как `*.v2.json`.
- Данные v3, созданные другой версией алгоритма или не подходящие к исходной эпохе,
  **не загружаются**: в предупреждениях пишется причина, исходная эпоха остаётся доступной.

## Ограничения

- Плиты в истории жёсткие, скорости постоянны, коллизия их не тормозит: за длинную историю
  континенты наезжают друг на друга дальше, чем на Земле.
- Топология плит не меняется: плиты не раскалываются и не сливаются; рифт раскрывает океан
  только по существующей границе.
- Отроги и долины гор в плане v3 расставлены по правилу. Реки v4 режут долины по stream
  power на гексах окна, но за 2 млн лет на гексах 75 км сеть перестраивается мало.
- Нет изостазии и изгиба литосферы: нет предгорных прогибов, горы не всплывают при размыве.
- Древние пояса есть только там, где v2 спаял континентальные блоки.
- Баланс эрозии внутри истории v3 диагностический (около 15 % снятого считается ушедшим из
  системы); баланс наносов v4 замкнут по каждому кубометру.
- Климат v4 — параметризация, а не модель циркуляции: нет сезонного хода, муссонов,
  океанских течений и радиационного баланса. Коэффициент стока выше земного (0,5 против
  ~0,4), высокие широты континентов холоднее (нет тёплых течений).
- Одно русло на гекс; дельт, рукавов, меандров и ледниковой эрозии нет. Пороги рек заданы
  в гексах, поэтому густота показанной сети зависит от разрешения.
- Высоты гор выдаёт PMGE, если библиотека собрана, иначе встроенный модуль.
- Макровысота v2 (исходная эпоха) — без деталей; детали есть только в `elevation_m` v3.
- Островные дуги, вулканические цепочки, атоллы, барьерные острова и типы берегов не
  генерируются. Мелкие острова возникают только из рельефа и уровня моря.
- `major_landmass_count` — цель. Если она недостижима, это пишется в предупреждениях вместе
  с фактическим числом.
- ID блоков и материков — номера связных компонент **в текущем окне**, по убыванию площади.
  В другом окне того же мира номера другие; сами формы совпадают.
- Мировая статистика (доля суши, число крупных массивов) считается на растре каркаса
  с ячейкой около 1/512 мира; массивы мельче ячейки туда не попадают.
- Идентичность результата гарантируется в одной среде; бит-в-бит совпадение между ОС
  не проверялось.
- В режиме `regional` область симуляции выводится из окна. Чтобы менять окно и разрешение
  в одном мире, задайте `simulation_bounds_km` и число плит явно (в GUI — флажок «Тот же мир»).
- После загрузки проекта с диска смена уровня моря мгновенна; смена снимка заново строит
  модели v2 (секунды — десятки секунд), но историю не пересчитывает.
- В снимке `t = 0` итоговая высота отличается от макровысоты v2 на структурный рельеф
  унаследованных гор и древних швов (сотни метров); плиты и суша коры совпадают с исходными.
