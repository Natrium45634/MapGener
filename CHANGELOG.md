# Журнал изменений

## HexWorld 1.1.0 (генератор 5.4.0) — 23.11.2026

Новая подсистема **вулканизм v5.1** (ТЗ 5.1): от источников магмы до извержений недавнего
окна (10 000 лет), их продуктов, опасностей и влияния на природу. Документация —
`docs/volcanism/`.

- **Источники из геологии.** Дуги субдукции, океанические и континентальные горячие
  точки, срединные хребты (трещинные поля), рифты (поля шлаковых конусов), грязевые вулканы
  переуплотнённых бассейнов. Случайного «декоративного» поля нет.
- **Система вулкана.** Источник, постройка, обстановка (суша / мелководье / глубоководье /
  подо льдом), статус (действующая / спящая / неясная / потухшая), фаза активности и
  лавовое озеро — это отдельные оси. Магма задаётся профилем: SiO₂, T, летучие, кристаллы,
  вязкость.
- **Баланс магматического очага.** Учитываются поступление, интрузии, застывание,
  извержения; невязка ~1e-15. Без расплава извержения нет. Частота извержений зависит от
  заполнения очага.
- **Детерминированные извержения.** Стабильные id `E-…`, стиль по вязкости, воде и
  открытости канала (гавайский … плинианский, фреатомагматический, подводный), разбиение
  массы (лава + тефра + газ = магма), высота колонны по Mastin, VEI по объёму тефры.
- **Продукты крупных и недавних извержений:**
  - лава — на локальной гексовой решётке 400 м, объём сохраняется точно, длина ограничена
    остыванием; на гекс идёт доля площади, а не весь гекс;
  - пепел — перенос по граням мировых гексов, 4 фракции, масса сохраняется;
  - пирокластические потоки — зона досягаемости (энергетический конус) отдельно от
    отложений;
  - лахары — только при наличии воды и рыхлого материала, по стоку v4;
  - подлёдные извержения — таяние ограничено энергией, прорывные паводки;
  - гидротермальные поля, новые острова, газовый стресс, импульсы аэрозолей SO₂ (только
    запись, без влияния на текущий климат);
  - ледяной мир (криовулканизм) — только в профиле `icy_world`.
- **Природа (v5.0).** Свежая вулканическая пустошь — доля гекса с восстановлением
  растительности по возрасту и климату. Новые особенности местообитаний: геотермальные,
  газовый стресс, гидротермальные источники дна.
- **Интерфейс.**
  - вкладка «Извержения (v5.1)» — 10 режимов;
  - раздел в «Информации о гексе»;
  - группа «Вулканизм» в настройках мира;
  - команда `hexworld volcanism`, `--through v51`;
  - сохранение `volcanism_fields.npz` и `volcanism.json`.
- **Тесты.** `tests/test_v51.py` — 93 теста. Сценарные миры — `tools/volcanism_scenarios.py`.

## HexWorld 1.0.1 (генератор 5.3.0) — 22.11.2026

Проверка баланса биомов на 12 мирах (разные сиды, центр карты на 0°, 15°, 30°, 50° и −30°)
и исправление найденного. Отчёт с таблицами — `docs/biome_balance.md`.

**Что нашла проверка**

- **Тайги не было ни в одном мире.** Причины:
  - климату не хватало континентальности на высоких широтах;
  - хвойные «начинали фотосинтез» только с +5 °C и проигрывали кустарничкам в коротком
    прохладном лете.
- **13 классов не могли появиться никогда.**
  - Входы туман и облачность приходили в классификатор нулевыми: синтетическая влажность
    воздуха была постоянной (50 % на суше).
  - Мангры были отключены («нужна модель приливов»).
  - Для низинных болот правила не было.
  - Бедленды перехватывало правило хамады.
  - И другие подобные причины.
- **Болот было слишком много:** 10–14 % суши, тропические заболоченные леса — 7,6 % суши.

**Что исправлено**

- **Климат (`climate-4`):**
  - открытые побережья на 40–70° теплее (океан переносит тепло);
  - моря, замерзающие зимой, делают берега континентальными (большая годовая амплитуда);
  - чуть больше годовая амплитуда морских берегов.
- **Топоклимат (`topoclimate-2`):**
  - влажность воздуха зависит от увлажнённости месяца (пустыня ~30 %, дождевой лес ~85 %);
  - адвективный морской туман на тёплых берегах;
  - облачный пояс гор считается от окружающих низин (~150 км), толщина пояса 1,8 км.
- **Растения:** хвойные и лиственница фотосинтезируют с 0–1 °C, широколиственные с 3 °C
  (Jarvis & Linder 2000).
- **Классы (`hexworld-biomes-2`):**
  - тайга считается лесом уже при сомкнутости ≥ 40 %;
  - «смешанный лес» — только при настоящей смеси пород;
  - пойменный лес — только на поймах; тропический получил свой класс;
  - болото — при стоячей воде ≥ 6 месяцев или ≥ 4 месяцев на очень плохо дренированной почве;
  - мангры, приморские марши и прибрежные себхи — полосой 0,6–4 км вдоль берегов
    соответствующего типа: доля гекса, а не весь гекс;
  - правила для низинных болот, сезонных пойм, засолённых болот бессточных впадин, такыров,
    гипсовых пустошей, бедлендов, субтропического сезонного леса, горного умеренного леса;
  - пороги облачного леса и туманной пустыни под реальный масштаб.

**Итог по 12 мирам** (было → стало)

- Классов суши, появившихся хотя бы в одном мире: 63 → 76 из 85.
- Тайга (все типы): 0 → ~3,4 % суши.
- Мангры: 0 → ~0,11 % (на Земле ~0,1 %).
- Горный облачный лес: 0 → ~0,9 %.
- Туманная прибрежная пустыня: 0 → ~0,1 %.
- Болота вместе с заболоченными лесами: ~14 % → ~8 % (на Земле 6–9 %).
- Засушливость не изменилась: засушливых земель ~40 %, пустынь ~18 %.

## HexWorld 1.0 (генератор 5.2.0) — 22.11.2026

Первая готовая версия для Windows: установщик, ничего не нужно знать о Python.
Версия программы — 1.0.0 (`PRODUCT_VERSION`); версия алгоритмов и формата данных —
5.2.0 (`GENERATOR_VERSION`), она продолжает внутреннюю нумерацию 1.0 … 5.1.

**Установщик для Windows** (`packaging/windows/`, `.github/workflows/windows-installer.yml`)

- Программа собирается PyInstaller в папку с `HexWorld.exe` (Python, Qt, numpy, scipy и
  `pmge.dll` внутри). Inno Setup делает из неё установщик на русском и английском.
- Установка без прав администратора, ярлыки в «Пуск» и на рабочем столе, удаление через
  «Приложения».
- Сборка проверяет программу дважды, командой `HexWorld.exe --self-test`: после
  упаковки и после тихой установки. Каждая проверка генерирует мир, экспортирует его и
  открывает окно. После проверки установленной программы сборка её удаляет.
- По тегу `v*` установщик прикрепляется к релизу.

**Карта и информация о гексе**

- **Карта стала плавной**:
  - сдвиг кадра 1–2 мс вместо 15–60 мс и подвисания на 130–190 мс;
  - карта режется на тайлы 256 px, они кэшируются, а недостающие дорисовываются в фоне;
  - при масштабировании виден растянутый прежний кадр;
  - реки, хребты и границы рисуются заранее в тайлы.
- **Управление картой**:
  - колесо — масштаб;
  - перетаскивание (левой или средней кнопкой) — сдвиг;
  - двойной щелчок — приблизить;
  - клавиши: + / −, стрелки, Home.
- **Панель «Информация о гексе»** справа открывается щелчком по гексу. В ней:
  - заголовок (суша/море, высота, биом, температура, осадки);
  - климатограмма;
  - разделы: положение, рельеф, тектоника и геология, климат, по месяцам, вода, почвы,
    высотная поясность, биомы, берег и дно, бассейн, все значения слоёв;
  - поиск по параметрам;
  - кнопки «Приблизить» и «Копировать».

  Модуль без Qt — `hexworld/hex_report.py`.
- **Названия** (`hexworld/names.py`):
  - океаны, моря, материки, горы, реки, озёра, пустыни, ледники;
  - постоянны для сида и написаны кириллицей;
  - на карте не перекрываются и появляются по мере приближения;
  - показываются и в панели гекса.

**Создание миров**

- **Эскиз мира** в окне «Новый мир»:
  - тот же сид и настройки на грубой сетке за 4–10 с;
  - пересчитывается сам после изменений (в фоне);
  - картинка нескольких слоёв и главные цифры.
- **Код мира «HW1-…»** (сид и изменённые настройки) — копировать и вставить в окне
  настроек; в CLI `hexworld generate --code` и `hexworld code PROJECT`.
- **Предупреждения о противоречивых настройках** (например, материков больше, чем плит;
  биомы без климата; очень холодный и влажный мир) и подсказка, на какие вкладки влияет
  параметр.
- **Частичный пересчёт**: окно настроек заранее говорит, какие этапы возьмутся из текущего
  мира и с какого начнётся пересчёт (конвейер и раньше переиспользовал неизменённые этапы).
- **«Мои миры»** (Ctrl+L):
  - каждый созданный мир попадает в историю: миниатюра, сводка, код;
  - есть избранное, переименование и поиск;
  - можно сгенерировать мир заново или открыть его в настройках;
  - можно сравнить два мира (таблица отличий).

  Хранится в `%APPDATA%\HexWorld`.
- **Пакет миров** (Ctrl+B) — до 60 эскизов разом: разные сиды, случайные настройки с
  вашими замками или полностью случайные. Двойной щелчок создаёт выбранный мир полностью.
- **Глобус** (Ctrl+G): мир на вращающемся шаре; видно, какую часть планеты занимает карта.
- **Экспорт для игровых движков** — в меню и как `hexworld export-game`:
  - карта высот 16 бит (PNG и RAW);
  - биомы (цвета и ID), вода, реки, температура, осадки;
  - таблица гексов CSV/JSON с осевыми координатами;
  - `world.json` с масштабом, легендами и названиями;
  - инструкция для Unity, Unreal и Godot.
- **Меню**: «Мир», «Вид», «Справка» (F1 — как пользоваться).

**Климат: пересохшие материки** (проверено на 8 мирах; было → стало, сравнение с Землёй)

- **Причина сухости.** Суша почти не возвращала влагу в воздух: испарение с суши было
  постоянной 0,0015. Теперь суша возвращает долю дождя, которая испаряется по кривой
  Будыко–Фу (как в водном балансе гекса); остальное уходит в сток.
- **Зависимость от разрешения.** Скорости выпадения и испарения считались на ячейку
  мировой сетки, а не на километр. Поэтому один и тот же мир при другом размере карты или
  разрешении каркаса имел другой климат. Теперь они пересчитываются по размеру ячейки:
  эскиз и полная карта согласуются.
- **Итог по 8 мирам**:
  - засушливые земли — было ~70 %, стало ~40 % (Земля ~41 %);
  - пустыни (P/PET < 0,2) — было ~33 %, стало ~18 % (Земля ~20 %);
  - осадки на суше — было ~590 мм, стало ~1080 мм (Земля ~800, допустимо 450–1300).

  Версия алгоритма — `climate-3` (климат сохранённых проектов пересчитывается).

**Скорость**

- Поле континентальной коры считается в ~1,9 раза быстрее при точно том же результате:
  отбрасываются ядра, которые заведомо не могут победить.
- Испарение с суши считается только по суше.

## 5.1.0 — 22.11.2026

  - 6 шаблонов размера и свой размер с оценкой времени и памяти;
  - 11 готовых миров;
  - сохранение и загрузка настроек в JSON;
  - кнопки «🎲 Случайные настройки», «🎲 Случайно и старт», «▶ Старт».
- **Окно прогресса**:
  - общий процент и текущий этап;
  - прошло / осталось / всего по наблюдаемой скорости;
  - список этапов;
  - «пульс», который идёт, даже когда этап молчит;
  - кнопки «Свернуть» и «Отмена».

  островных дуг.
- Тесты: `tests/test_world_settings.py`. Проверяются:
  - покрытие схемы;
  - обратимость значений;
  - замки;
  - 300 случайных наборов;
  - готовые миры;
  - монотонность прогресса;
  - окно на offscreen Qt.

## 3.0.0 — 15.11.2026

Третья ступень: геологическая история, горы, вулканизм, ограниченная эрозия.

| Шаг ТЗ | Реализовано | Проверено | Ограничение |
|---|---|---|---|
| A. Подготовка | матрица алгоритмов и лицензий в `docs/RESEARCH.md` | лицензии — по страницам репозиториев | архив с досье и ТЗ PMGE в сессию не пришёл; исходники чужих проектов не читались |
| B. История | время, подшаги, точная кинематика плит, перекрытия и разрывы, снимки, журнал событий | тесты на искусственных мирах; снимки различаются | плиты жёсткие, скорости постоянны, топология не меняется |
| C. Орогенез | системы, главный хребет, ветви, отроги, вершины, перевалы, долины, устойчивые ID | связность, седловины, непрерывность, отсутствие швов | отроги и долины по правилу, не из стока |
| D. Адаптер и вулканизм | адаптер backend'ов, референсный backend; горячие точки, дуги, возрастные цепочки | сторона дуги, цепочка, отсутствие вулканов при сдвиге и коллизии | **PMGE не интегрирован**: только загрузка и сверка ABI; дуги слишком густые |
| E. Возраст и эрозия | возраст коры, породы и сопротивление, склоновая и стоковая эрозия, осадки, древние швы | износ гор, неотрицательность, баланс | растр ~60 км; баланс не замкнут локально; нет изостазии |
| F. GUI и экспорт | вкладки «Геоистория», «Рельеф», «Вулканизм»; выбор снимка, инспектор, масштаб интерфейса; CLI `history`, `epoch`, `events` | offscreen-тесты, PNG всех вкладок | на экране, на Windows и на 1000×800 GUI не запускался |

**Почему так**

- Контур плиты в момент `t` получается точным жёстким преобразованием исходного. Перенос
  по шагам на растре я отбросил: при шаге меньше ячейки контуры не двигаются вовсе.
- Типы взаимодействий выводятся из геометрии (перекрытие и разрыв), а не из знака скорости
  на границе: так сразу получаются ширина зоны и её история.
- Память породы хранится в материальной системе плиты; иначе горный пояс размазывался бы
  по мантийной системе на сотни километров.
- Возраст новой коры считается как доля расстояния между осью спрединга и старой окраиной.
  Первый вариант («время первого открытия ячейки») давал старую кору на оси; тест на
  расходящихся плитах это поймал.
- Древние пояса добавлены вдоль швов, по которым v2 спаял блоки: без этого все
  унаследованные горы лежали на действующих границах и заново поднимались.

**Совместимость форматов**

- Схема `hexworld-project-3`; проекты схем 1 и 2 открываются.
- Файлы v1 и v2 при добавлении v3 не меняются. Новые файлы: `history_fields.npz`,
  `history.json`, `events.json`, `checkpoints.npz`, `mountain_plan.json`.
- `config.json` получил разделы `history` и `mountains`; исходные `config.json` и
  `manifest.json` проекта v2 сохраняются как `*.v2.json`.
- Алгоритмы v1 и v2 не менялись (`tectonics-1`, `continents-1`): хэши их полей те же.
  Новые: `geohistory-1`, `mountains-1`.
- Данные v3 другой версии алгоритма не загружаются, причина пишется в предупреждениях.

**Изменения в поведении прежнего кода**

- `generate()` по умолчанию выполняет и стадии v3 (`through="v3"`).
- `project.layer("land_mask")` и другие одноимённые слои возвращают выбранную эпоху v3,
  если она есть; исходная эпоха — через `project.baseline_layer(...)`.
- Вкладка «Высоты» по умолчанию показывает итог v3; исходная макровысота — отдельный режим.
- Запланированные вкладки переименованы: температура, осадки и влажность, гидрология и
  реки, биомы, геосимволы, сейсмичность.

**Не закрыто** — см. `docs/STATUS.md` и `docs/REALISM_ANALYSIS.md`.

Вторая ступень: континентальные блоки, макрорельеф, уровень моря, вкладки просмотрщика.

**Сделано**

- метаданные блоков и материков: площадь, центр, границы, доли плит, площадь суши и
  подводной части, взаимные связи;
- два режима моря; смена уровня пересчитывает только сушу, материки и шельф;
- реестр вкладок `views.py`; GUI с вкладками «Плиты / Материки / Высоты», общим масштабом
  и выделением, легендами, отменой генерации;
- CLI: `continents`, `sea`, `views`, `export`, `render --view`;
- API: `generate_v2`, `generate_continents`, `generate_macro_relief`, `derive_landmasses`,
  `get_layer`.

**Почему так**

- Материки и высоты — функции мировых координат, как и плиты в v1.0. Иначе смена окна или
  разрешения меняла бы мир.
- Граф границ v1.0 привязан к гексам окна, поэтому для v2 границы плит прослеживаются
  отдельно в мировых координатах.
- Суша выводится только из высоты и уровня моря; отдельной «карты океана» нет.

**Что пробовал и отбросил**

- Узкие прямые перемычки между блоками давали заметные «палочки». Заменены широкими зонами
  спайки, соразмерными меньшему блоку.
- Принудительные прямые рифты для профиля `fragmented` давали «царапины». Заменены
  уменьшением масштаба узора коры и усиленным утонением вдоль расходящихся границ.
- Сильное радиальное стягивание для `supercontinent` вытягивало массивы лучами. Оставлено
  слабое стягивание плюс широкое поднятие коры в центре.

**Совместимость форматов**

- Схема проекта `hexworld-project-2`. Проекты `hexworld-project-1` открываются.
- Файлы v1 (`plates.json`, `fields.npz`, `boundaries.*`) при добавлении v2 не меняются;
  новые данные — в `continental_fields.npz` и `continents.json`.
- `config.json` получил разделы `continents`, `relief`, `sea`. При обновлении проекта v1
  исходные `config.json` и `manifest.json` сохраняются как `*.v1.json`.
- Алгоритм v1 не менялся: `tectonics-1`, те же хэши полей. Алгоритм v2: `continents-1`.
- `geology_hash` по-прежнему считает только поля v1; у v2 свой `geo_hash`.

**Изменения в коде v1.0**

- `generate()` получил параметр `through` и по умолчанию выполняет и стадии v2.
- Если ключи всех стадий v1 совпадают с `reuse`, массивы v1 берутся как есть, без пересчёта.
- Прогресс-колбэк может прервать генерацию исключением `GenerationCancelled`.
- Выбор плиты в GUI заменён выбором гекса: один щелчок показывает данные всех слоёв.

**Не закрыто**

- запуск GUI на Windows и на реальном экране не проверялся;
- зоны спайки блоков слишком прямые; `supercontinent` не всегда даёт один доминирующий массив;
- адаптер PMGE — только данные, без кода адаптера.

Полный реестр статусов — `docs/STATUS.md`.

## 1.0.0 — 14.11.2026

  в `boundaries.json`;
- в `fields.npz` добавлены слои `continentality_km`, `velocity_x`, `velocity_y`,
  `boundary_type`.
